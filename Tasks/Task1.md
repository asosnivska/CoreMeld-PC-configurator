## Назва
CoreMeld - розумний підбір комп'ютерних комплектуючих

## Проблема
Проблема полягає у відсутності зручного інструменту для безпомилкового підбору комп'ютерних комплектуючих та автоматичної генерації збірок під заданий бюджет.
* **Для звичайних користувачів:** Важко самостійно підібрати деталі для ПК через брак технічних знань. Користувачі з певним бюджетом часто не розуміють будову комп'ютера, не знають, як правильно розподілити кошти між компонентами, та не мають впевненості у тому, чи підійде одна деталь до іншої при покупці.
* **Для сервісів (продаж, ремонт, збірка):** Процес підбору деталей під індивідуальні потреби та бюджет кожного клієнта займає багато часу. Бракує автоматизованого генератора, який би швидко створював кілька надійних варіантів збірок під різні запити без необхідності ручної перевірки сумісності.

## Цільові користувачі
* **Звичайні користувачі (покупці):** Люди, які хочуть зібрати або оновити комп'ютер, але не мають технічного бекграунду. Вони хочуть легко вказати свій бюджет та призначення ПК, отримати готовий список покупок і бути впевненими, що всі деталі гарантовано підійдуть одна до одної.
* **Спеціалісти сервісів та магазинів:** Консультанти, майстри з ремонту або продавці комп'ютерної техніки. Їм потрібен ефективний інструмент для швидкої генерації конфігурацій, щоб оперативно пропонувати клієнтам оптимальні варіанти під їхній бюджет.

## Мета
Розробити десктопний застосунок для підбору комп'ютерних комплектуючих, який дозволить звичайним користувачам без спеціальних знань легко збирати ПК під свій бюджет (потреби), а сервісним центрам - ефективно генерувати варіанти конфігурацій для клієнтів із повною гарантією їхньої сумісності.

## Короткий опис основних можливостей
* Продукт працює як розумний конфігуратор та генератор збірок.
* Користувачі можуть вказати цільовий бюджет і потреби (наприклад, офісна робота, ігри, рендер), після чого система автоматично підбере оптимальні деталі, не вимагаючи від користувача розуміння архітектури ПК.
* Для сервісних центрів реалізовано розширені інструменти масової генерації варіантів збірок для швидкого обслуговування клієнтів.
* Для гарантії надійності та безпеки покупок, застосунок використовує суворі алгоритми перевірки характеристик, що на 100% гарантує сумісність обраних компонентів між собою (форм-фактори, сокети, живлення тощо).

## За що відповідає кожна роль

### C# / .NET Developer:
* Написання коду мовою C# на платформі .NET та реалізація функціональності відповідно до переліку завдань.
* Робота над змінами в окремих гілках та їх перенесення до основної гілки виключно через запити на включення змін (Pull Requests).
* Командна взаємодія: участь в обговоренні технічних рішень та обов'язковий перегляд коду (Code Review) інших учасників команди перед злиттям суттєвих змін.
* Аналіз та рефакторинг проблемних ділянок.

### Core Logic Lead (Архітектор):
* Визначення загальної структури проєкту та розподіл на шари.
* Проєктування технічних UML-діаграм.
* Налаштування глобальної обробки помилок, валідацію вхідних даних та журналювання (логи).
* Контролювання дотримання архітектурних патернів.
* Створення початкових рішення (Solution) на платформі .NET та обґрунтування архітектурних рішень.
* Відповідальність за документацію опису архітектури та ключових технічних рішень.

### Data Lead (Розробник БД):
* Проєктування реляційної бази даних та створення ER-діаграми.
* Нагляд над іншими розробниками, щоб вони правильно писали запити до бази і не ламали структуру даних.

### Security & Reliability Lead (Відповідальний за безпеку та стабільність):
* Керування безпекою застосунку: стежити, щоб секретні дані не зберігалися у відкритому коді, та проводити перевірку безпеки.
* Підготовка короткого переліку перевірених ризиків і виконаних заходів для фінального захисту.
* Створення системи запису історії роботи програми (логів) і несення відповідальності за те, щоб усі критичні дії системи та непередбачувані помилки автоматично зберігалися у файл.
* Налаштування механізму перехоплення непередбачуваних помилок на рівні всього застосунку для запобігання його раптовому закриттю.
* Розробка та впровадження правил перевірки всіх вхідних даних від користувача.

### QA & CI Engineer (Автотести та інтеграція):
* Визначення стратегії тестування та написання автоматизованих тестів.
* Налаштування GitHub Actions для автоматичного збирання проєкту (CI) при кожному коміті.
* Контроль над тим, щоб тести автоматично запускалися і проходили успішно.
* Створення інтеграційних тестів, перевірка крайових ситуацій, проведення фінального тестування.

### UI/UX Lead (Відповідальний за інтерфейс):
* Реалізація вікон десктопного застосунку.
* Забезпечення єдиного стилю оформлення, стандартизації елементів керування та загальної зручності користувацького інтерфейсу.
* Налаштування прив'язки даних та обробників подій для інтеграції візуальної частини з бізнес-логікою: передача вхідних даних від користувача до системи та коректне відображення результатів.

### Docs Lead (Документація):
* Несення відповідальності за те, щоб проєкт був правильно оформлений для здачі.
* Підтримання в актуальному стані файлу README.
* Збирання всіх UML-діаграм, архітектурних документів та підготовка матеріалів для фінальної презентації.
* Створення початкового репозиторію на GitHub.
* Запис історії користувача та критеріїв приймання для основної функціональності.
